# Abstract

Android is the most widely used mobile operating system in the world. Naturally, this makes it a frequent target for attackers. In recent years, Google has significantly strengthened Android's baseline security. Mechanisms like SELinux and strict kernel sandboxing have made it much harder to exploit standard apps or attack the kernel directly. Because of this, attackers have started focusing on native system services. These services—especially the ones running inside proprietary Hardware Abstraction Layers (HALs)—act as a bridge between the physical hardware and the operating system. If an attacker compromises a HAL service, they can often escalate their privileges and gain deep system access.

However, finding bugs in these services using automated fuzz testing is notoriously difficult. The problem lies in how these services communicate. They use Inter-Process Communication (IPC) mechanisms like `ioctl` and Binder, which expect data to be formatted in very specific, rigid structures. If a traditional fuzzer just sends random or slightly mutated bytes, the service will reject the input almost immediately during the initial parsing stage. The fuzzer essentially gets blocked before it can reach any meaningful code.

This seminar thesis looks at how "interface-aware fuzzing" has evolved to solve this exact problem on Android. I will trace the development of this methodology, starting from early attempts that used static source code analysis, all the way to recent techniques relying on dynamic binary instrumentation. The thesis focuses on three main research systems: DIFUZE (which analyzed kernel `ioctl` interfaces using static bitcode), FANS (which mapped stateful Binder dependencies by extracting Abstract Syntax Trees), and NASS, which is the primary focus of this paper.

The main issue with tools like DIFUZE and FANS is what we can call the "open-source blind spot." The most critical native services on modern phones are closed-source, proprietary binaries. Static analysis tools simply can't read them. NASS gets around this limitation by taking advantage of universal Remote Procedure Call (RPC) design principles. It uses a technique called Deserialization-Guided Interface Extraction (DGIE) to reverse-engineer interface definitions on the fly, without needing any source code. Additionally, NASS uses Dynamic Binary Instrumentation (DBI) to extract clean, thread-specific coverage data from chaotic, multi-threaded background daemons.

By examining these three systems together, I aim to show why interface awareness is absolutely critical for modern fuzzing. Without it, finding deep memory-corruption bugs in the proprietary layers of today's mobile devices is practically impossible.
