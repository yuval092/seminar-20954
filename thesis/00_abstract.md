# Abstract

The attack surface on Android has shifted fundamentally. As Google hardened the core OS with SELinux and kernel sandboxing, the "easy" exploits in high-level apps and the direct kernel syscall interface started to dry up. Attackers responded by moving into the native system services that populate the Hardware Abstraction Layer (HAL). These proprietary binaries bridge the gap between physical hardware and the core OS. Because they often run with elevated permissions, a single compromise here provides a perfect pivot point for privilege escalation.

Testing these services is a structural nightmare for traditional tools. They rely on rigid IPC mechanisms like `ioctl` and Binder, which means a standard fuzzer's random byte mutations are almost always bounced at the front door. Simple problem. Massive impact. The inputs fail initial parsing checks long before they can even touch the service's internal logic. 

This thesis examines the evolution of interface-aware fuzzing—the transition from static source-code analysis to the messy reality of dynamic binary instrumentation. We evaluate three foundational systems. DIFUZE mapped kernel drivers using LLVM bitcode. FANS extracted stateful dependencies from ASTs. NASS, by contrast, targets the proprietary "blind spot" that static tools cannot reach. Ultimately, this progression shows that interface awareness is no longer just an optional optimization. Without a map of these input structures, auditing the proprietary layers of modern mobile devices is, for all practical purposes, basically impossible — at least at any useful scale.
