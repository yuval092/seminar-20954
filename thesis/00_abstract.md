# Abstract

Android's attack surface has shifted fundamentally. As Google hardened the core OS with SELinux and kernel sandboxing, the "easy" exploits in high-level apps and the direct kernel syscall interface began to dry up. Attackers responded by moving into the native system services that populate the Hardware Abstraction Layer (HAL). These proprietary binaries bridge the gap between physical hardware and the core OS, and because they often run with elevated permissions, a single compromise here provides the perfect pivot point for privilege escalation.

Testing these services is a structural nightmare for traditional tools. Because they rely on rigid IPC mechanisms like `ioctl` and Binder, a standard fuzzer's random byte mutations are almost always bounced at the front door. The inputs fail initial parsing checks long before they can touch the service's internal logic. This thesis examines the evolution of "interface-aware" fuzzing—a transition from static source-code analysis to the messy reality of dynamic binary instrumentation. We evaluate three foundational systems: DIFUZE, which mapped kernel drivers using LLVM bitcode; FANS, which extracted stateful dependencies from ASTs; and NASS, which targets the proprietary "blind spot" that static tools cannot reach. Ultimately, this progression shows that interface awareness is no longer an optional optimization. Without a map of the expected input structures, auditing the proprietary layers of modern mobile devices is effectively impossible.
