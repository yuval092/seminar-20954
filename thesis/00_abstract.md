# Abstract

Android's massive user base naturally makes it a prime target for attackers. Over the years, Google has significantly hardened the operating system's security posture. With mitigations like SELinux and strict kernel sandboxing in place, finding simple application flaws or direct kernel exploits has become much harder. As a result, the attack surface has shifted toward native system services. Specifically, services running within proprietary Hardware Abstraction Layers (HALs) have become a focal point, as they bridge the gap between physical hardware and the core OS. A compromised HAL service often provides attackers with the privilege escalation needed to gain deep system access.

Testing these services automatically with fuzzing, however, is a major challenge. These services communicate through Inter-Process Communication (IPC) mechanisms like `ioctl` and Binder, which require inputs to follow strict, predetermined structures. Traditional fuzzers that rely on random byte mutations fail almost immediately against these interfaces. Their inputs are rejected during the initial parsing phase, long before the fuzzer can explore the actual business logic of the service.

This seminar thesis explores how "interface-aware fuzzing" evolved to overcome these structural roadblocks on Android. It traces the shift from static source code analysis to modern dynamic binary instrumentation. I focus my analysis on three key research systems: DIFUZE, which mapped out kernel `ioctl` interfaces using LLVM bitcode; FANS, which extracted Abstract Syntax Trees (ASTs) to model stateful Binder transactions; and NASS, which targets the proprietary services that the first two systems missed.

The core limitation of early tools like DIFUZE and FANS is their dependence on open-source code. Today, the most privileged native services on a commercial phone are closed-source, proprietary binaries, which makes static analysis nearly impossible. NASS solves this "open-source blind spot" by relying on universal Remote Procedure Call (RPC) design principles. Through a technique called Deserialization-Guided Interface Extraction (DGIE), it dynamically figures out interface definitions without needing any source code. NASS then combines this with Dynamic Binary Instrumentation (DBI) to pull clean, thread-specific coverage data from noisy, multi-threaded daemons.

By examining these three systems together, this thesis highlights why interface awareness is a non-negotiable requirement for modern fuzzing. Without a clear map of the expected input structures, uncovering deep memory-corruption bugs in the proprietary layers of today's mobile devices is practically impossible.
